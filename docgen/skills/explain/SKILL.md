# 説明ドキュメントの作成

出力には以下のスキルの利用を推奨する。

- `docgen:html`: HTML でドキュメントを生成する
  - ただし、ユーザーが別の形式を指示した場合や、作業リポジトリに適切な形式がある場合はそれに従う
- `docgen:writing`: 日本語の技術文書を自然な表現にするための規範

## 構成

対象読者と読後に理解してほしいことを定める。
素材の順序を引き継がず、説明の中心となる問いに沿って、前提と関係を追えるように構成する。
冒頭で全体像と要点を示し、抽象的な説明は具体例と結び付ける。

次の流れを基本とする。

1. 背景と要点
2. 本論
3. 具体例
4. 補足、限界、関連事項

この並びを固定の章立てとせず、説明の目的に応じて統合、省略、並べ替えを行ってよい。

## 方針

対象読者に前提知識がない場合は、身近な例で対象の目的を示し、主要な要素と関係を図で示してから、必要な概念と仕組みを段階的に説明する。

複数の節で使う専門用語があり、読者が参照し直す必要がある場合は、用語リストを含める。
表、タイムライン、図は、関係を視覚的に示した方が理解しやすい場合に使う。
単純な手順は番号付きリストで示し、必要性なく図にしない。
一つの図では中心となる一つの関係を扱い、図中の要素は本文でも説明する。

原典に説明上重要な図がある場合は、出典を明示し、原典へリンクして引用する。
引用できない場合は原典の図を模写せず、説明に必要な事実と関係を独自の構成で示す。具体的な書式と描画方法は、出力形式に合わせる。
