# docgen 設計メモ

テキストベースの成果物を作るプラグイン。現在は HTML ドキュメントを書く `html`
スキルのみを想定している。今後スキルを追加する余地を残した名前にしてある。

出発点は `mathbullet/skills/plugins/html`。**それより優れたものを作る**のが目標。

## 要求

### 引き継ぐ点

mathbullet の良かったところ。

- デザインシステムを持ち、見た目の判断を書き手にさせない
- マークアップの指示が明確
- 用語集を横に置く 2 カラム構成
- SKILL.md が簡潔 (mathbullet は 110 行)

### 解決する不満点

| 不満点 | 方針 |
| --- | --- |
| 用語集内で余計な左右スクロールが出る | 列幅を固定して溢れさせない |
| 用語集がなくても幅が狭いまま | 用語集の有無で 1 カラム / 2 カラムを自動切替 |
| 数式のフォントが反映されていない? | 要調査 |
| TeX 形式でコピーしたい | コピー機能を持たせる |

### 成果物の形

- **既定は単一ファイル**。ユーザーが受け取って持ち歩けることを優先する
- 分離した状態 (HTML + CSS) を渡すのは、複数ドキュメントで CSS を共有するときと、
  デザインシステム自体を求められたときだけ
- 「シングルファイルで」と指示されても、**まず分離して書き、最後にバンドルする**。
  書いている途中は普通の HTML/CSS として扱えたほうが編集しやすい

### 外部依存

- **CDN 参照のまま**が既定。成果物を軽く保つ
- `--offline` 相当の手段で CDN 資産も埋め込めるようにする。ネットワークのない環境向け
- ライブラリをプラグインリポジトリにコピーしない。バンドル時に取得して成果物に入れる

### 色

有彩色は 2 色だけに絞る。リンク/キーワード用と、アクセント/強調用。

- teal `#008080` をテーマカラーとして固定する。pokutuna.com は参考であって制約ではない
- diff の緑赤は差分表示専用の機能色とし、本文の装飾には使わない

### ダークモード

- `prefers-color-scheme` に追従しつつ、トグルボタンで明示的に上書きできる
- 選択を localStorage に保存する
- 描画前にテーマを確定させ、ちらつきを防ぐ

### 可視化

- 自作の図はインライン SVG。線をテーマに追随させる
- フローチャート・シーケンス図・状態遷移図は Mermaid。描画したうえで
  元のソースをコピーできるようにする
- アスキーアートと、絵文字・矢印文字を図記号に使うことは禁止

### SKILL.md の分量

**mathbullet の 110 行と同等か、それより短く保つ。** HTML を出力することに
特化させ、長くしない。

そのために **判断はできるだけ CSS 側に寄せる**。書き手がやるのはクラスを当てる
ことと最小限のマークアップだけ、という状態を目指す。長いコード例は SKILL.md に
書かず、見本ファイルを参照させる。

### スコープ外

**「説明的でわかりやすい内容を作る」ことは別スキルとして分ける。**
`html` スキルは HTML 成果物を作ることに専念する。内容の質に関する指示はそちらへ。

## 調査で分かったこと

- **数式のフォントに問題はない。** MJXTEX は正しく適用されている
- **用語集の横スクロールは `white-space: nowrap` を外すだけでは直らない。** 列幅の固定が要る
- **teal `#008080` は暗背景で 3.79:1 しかなく AA を満たさない。** ダーク用の
  明るい変種が必須
- アクセント色に orange `#C2410C` を選ぶと、色相 17° が diff の削除色 (17°) と
  完全に衝突する。amber 系 (26°) なら衝突しない

### バンドル方式

バンドルは標準ライブラリだけの自前スクリプトで行う。**vite + vite-plugin-singlefile** は使えない。

- 素の `<script src>` は vite が黙って落とし、壊れたローカル参照が残る
- `type="module"` にすると埋め込めるが、モジュールの遅延実行で数式スクリプトが
  MathJax 起動後に走り、コピーボタンが付かなくなる
- テーマのちらつきも再発する

### バンドル実装の注意

- 処理順は **stylesheet → 画像 → script** で固定する。画像を script より後に
  処理すると、インライン化された mermaid の圧縮 JS 内にある `<image href="${e}">`
  を画像参照と誤検出する
- 同じ理由で `${` を含む参照はスキップするガードが要る

## 検証の方法

**DOM の検査はレイアウトの検証にならない。** 次の 3 件はいずれも DOM 上は正常に見えていた。

| 見逃したもの | DOM 検査の結果 | 実際 |
| --- | --- | --- |
| インライン数式のコピーボタンが `opacity: 0` かつ `position: static` | 「数式は描画された」「コピーは動く」= 両方 Yes | 非表示なのに 40px を行内で占有し、数式の直後に穴が空く |
| テーマカラーが画面に出ていない | 「リンクの色は正しい」= Yes | 本文にリンクが 1 つもなく、teal がどこにも現れない |
| `.dg-table-scroll` が機能しない | クラスは CSS に存在する | `table { width: 100% }` を継承して包んでも横スクロールしない |

いずれもスクリーンショットでしか検出できない。DOM は「クラスが存在するか」
には答えるが、「そのクラスが仕事をしているか」には答えない。

### 守ること

- **成果物は必ずレンダリングして目視する。** DOM 検査はその代わりにならない
- **SKILL.md に載せる部品は必ず見本ファイルにも実例を置く。**
  見本にない部品は動作が確認されないまま壊れる (`.dg-table-scroll` がこれに当たる)
- 見本ファイル自体も目視する。マークアップの正とするなら、それが正しく
  描画されることを確認していなければ意味がない

## 実装の判断

- 数式は MathJax の **SVG 出力** (`tex-svg-full.js`) にした。CHTML はフォントと拡張を実行時に
  CDN から取るため、インライン化するとオフラインで壊れる。SVG 出力は全部入りで追加ロードがない
- 用語集は表ではなく `dl` にした。狭い列で語中折り返しが起きる問題が構造ごと消える
- 用語集なしのときは `main` ではなく `.dg-page` 全体を狭める。h1 だけ幅いっぱいになる
  ちぐはぐを避ける
- `screenshot.sh` は Chrome が終了しないことがあるので、PNG が出たら kill する。ダークは
  一時コピーに `data-theme="dark"` を打って撮る (OS 設定に依存しない)
- `bundle.py --offline` の成果物は Web フォント込みで 27 MB、`--no-webfonts` を足すと 6 MB

## デザインの判断

### 色

- ダークの背景と面のコントラストは 1.15:1 では足りず、ブロックが背景に沈む。背景 `#1A1D22`、
  面 `#232830`、枠 `#4A5262` で段差をつける
- teal は書き手個人のアイコンカラーなので、h1 の文字と h2 の左の四角に使う。h1 は teal の文字と
  下線、h2 は左の teal の四角で示す。四角のほうが下線より節の始まりが目立ち、ページをたどりやすい。
  h3 の文字は teal にしない。ダークでは teal の点が多すぎて散り、h3 はリンクとサイズが近いので
  クリックできそうに見える
- teal は他に note のラベル、steps の番号、目次の番号に使う
- 図と chip 用の系列色 `c1`〜`c5` を持つ。pokutuna.com のパレット (teal, `#0072B2`, amber, pink,
  purple) を基に Okabe-Ito 系で揃え、ダークは明るい変種。`figure svg` と `.dg-chip` の中でしか
  効かないので、本文の「有彩色は 2 色」は崩れない
- 節番号を振るような構造上の装飾は持たない。見出しの階層は文字サイズと teal の四角だけで示す

### 部品

- 表には外枠 (`--dg-border`) を付ける。内側の罫線は `--dg-rule`
- コードブロックにも copy ボタンを付ける。copy.js が `pre:not(.dg-mermaid)` を `div.dg-code` で包み、
  Mermaid と同じ位置 (右上、hover で表示) に置く。`pre` 自体は横スクロールするので、包む div に
  絶対配置する
- タイトル周りは `header.dg-header` → h1 → `p.dg-lede` の 3 つ。書誌情報はヘッダーに集約し、左に分類や
  テーマ、右に日付・版・実験番号など文書を特定する印を置く。h1 の下に別のメタ行を設けると、ヘッダーと
  同じ書式の行が 2 つ並び、役割の違いが読み取れない。h1 は 34px
- ブロックは強調 (`.dg-note`) と補助情報 (`.dg-sub`) の 2 種類。強調は白地に枠で本文から浮かせ、
  補助情報は `--dg-surface-alt` の面に置いて流れを切らない。種別は `data-label` の語で示し、色は
  変えない。ラベルは省ける
- `.dg-note` のラベルは枠にまたがる teal のタグにする。ラベルを箱の中に収める形 (mathbullet の
  要点ボックス) は本文の見出しと見分けがつかない。タグにすると箱の外に出るので、中身と役割が分かれる。
  ラベル文字をやめて色の帯だけを置く案は、種別を語で示せなくなるため採らない
- 目次は `.dg-sub` と同じ体裁にし、「目次」のラベルを CSS で付ける。目次専用のコンポーネントは
  持たない。項目は teal の等幅番号で 1 列に並べる。白地に黒枠の箱は補助情報にしては本文から浮き、
  複数列に分けると読む順序が分かりにくい
- 箇条書きは素の `ul` / `ol`。マーカーだけ muted
- main 内の h2 / h3 には anchor.js が `#` のアンカーリンクを付ける (hover / focus で表示、teal の等幅)。
  id の無い見出しには文面から id を生成し、重複には連番を足す。用語集の h2 には付けない。
  CSS の `::before` で `#` を出す方法では href を持てないので JS にした
- `skills/html/template.html` に `<head>` の読み込み順と骨格を置き、コピーして書き始める。
  読み込み順の説明は SKILL.md ではなく template のコメントに書く

### 幅 (`.dg-wide`)

Quarto の article layout を参考にした。幅は「本文幅か画面幅か」の 2 択に留め、マージンノートや
キャプションの横出しは持たない (右カラムは sticky な用語集が占めていて両立しない)。

- はみ出しは左右均等で、画面を基準に中央寄せする。幅は `min(100vw - 64px, 1600px)` で、Quarto の
  `screen-inset` に相当する。本文 (main) を中心に対称にはみ出す設計では、main が左寄りなので左端に
  阻まれ、1280px で片側 120px しか広がらない。右にだけ伸ばす設計は、はみ出しが左右非対称になる
- margin-left は main の左端の画面座標 (`(100vw - 1100px) / 2 + 48px`、1 カラムでは `--dg-measure`
  基準) から逆算する。1000px 以下では無効
- `.dg-grid.dg-wide` に `figure` を並べると、複数の図を横に並べるブロックになる (Quarto の
  multi-column figures)。用語集の上を通る分は背景色と z-index で隠す
- `.dg-table-scroll` や `figure` の margin 指定が後勝ちで margin-left を打ち消すため、
  `.dg-page .dg-wide` で特異性を上げている
- 見本の `.dg-table-scroll` には `.dg-wide` を付けない。幅が足りるとスクロールが起きず、
  「スクロールする表」を示せなくなる。部品としては組み合わせられる

### 見本

- 横長画像のプレースホルダ (`figure.dg-wide`、`.dg-grid.dg-wide` に 3 枚) を破線の SVG で置く
- 引用は 1 例だけにし、`cite` 内リンクもそこに含める
- タイトルは「docgen HTML ドキュメント デザインシステム」
- 見本は、文書を組み立てるときの判断順に「レイアウト」「ブロック」「本文」から始める。
  「色のトークン」は色指定が必要になる図の直前に置く。載せるのは書き手が図やページ固有の
  `<style>` で自分で指定する 6 つだけで、CSS が自動で当てる変数 (本文の文字色、枠線など) は
  載せない。カラーコードは書かず、見本は `style="background: var(--dg-*)"` で描くのでテーマに追随する
- 見本の本文、カード、用語集、コード、図、数式は、可能な限り docgen とデザインシステム自体を
  説明する内容にする。マークアップを探す書き手に、無関係な題材の理解を要求しない
- 全トークンと内部の規則は `design-system/DESIGN_SYSTEM.md` に置く。開発者向けの資料で、
  エージェント向けの指示は SKILL.md と見本ページが持つという分担 (mathbullet と同じ)
- `pre.dg-diff` の `code` は `white-space: normal` にする。span を改行で区切って書くと、
  その改行が `pre-wrap` で 1 行として描かれ、差分が 1 行おきに空く。行間も 1.5 に詰めた
